# 02 — Database Schema và SQL khởi tạo

## Đọc trước khi chạy
- Mở Supabase Dashboard → Table Editor để kiểm tra bảng hiện có.
- Nếu đã có bảng cùng tên, không chạy nguyên xi trước khi đối chiếu schema.
- Chạy SQL trong SQL Editor bằng tài khoản quản trị project.
- Kiểm tra RLS/policies sau khi tạo.
- Schema dưới đây là bản khởi đầu cho **mỗi tài khoản chỉ xem/sửa giao dịch do chính mình tạo**. Nếu cần dùng chung dữ liệu cho cả đội ngũ, phải thiết kế `organizations`, `organization_members` và role-based RLS trước khi dùng dữ liệu thật.

## SQL khởi tạo
```sql
-- Business units
create table if not exists public.business_units (
  id bigint generated by default as identity primary key,
  code text not null unique,
  name text not null,
  is_active boolean not null default true,
  created_at timestamptz not null default now()
);

insert into public.business_units (code, name)
values
  ('SON_MAI', 'Sơn Mài'),
  ('FNB', 'F&B'),
  ('VAN_PHONG', 'Văn phòng')
on conflict (code) do nothing;

-- Categories
create table if not exists public.categories (
  id bigint generated by default as identity primary key,
  name text not null,
  transaction_type text not null check (transaction_type in ('income','expense')),
  business_unit_id bigint references public.business_units(id),
  created_by uuid references auth.users(id),
  is_active boolean not null default true,
  created_at timestamptz not null default now()
);

-- Cash/bank accounts
create table if not exists public.cash_accounts (
  id bigint generated by default as identity primary key,
  name text not null,
  account_type text not null check (account_type in ('cash','bank','other')),
  opening_balance numeric(18,2) not null default 0,
  created_by uuid not null default auth.uid() references auth.users(id),
  is_active boolean not null default true,
  created_at timestamptz not null default now()
);

-- Transactions
create table if not exists public.transactions (
  id bigint generated by default as identity primary key,
  transaction_date date not null default current_date,
  business_unit_id bigint not null references public.business_units(id),
  category_id bigint references public.categories(id),
  cash_account_id bigint references public.cash_accounts(id),
  transaction_type text not null check (transaction_type in ('income','expense')),
  amount numeric(18,2) not null check (amount > 0),
  payment_method text not null check (
    payment_method in ('cash','bank_transfer','card','other')
  ),
  description text,
  reference_no text,
  created_by uuid not null default auth.uid() references auth.users(id),
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

create index if not exists idx_transactions_date
  on public.transactions(transaction_date);
create index if not exists idx_transactions_unit_date
  on public.transactions(business_unit_id, transaction_date);
create index if not exists idx_transactions_created_by
  on public.transactions(created_by);

-- Enable RLS
alter table public.business_units enable row level security;
alter table public.categories enable row level security;
alter table public.cash_accounts enable row level security;
alter table public.transactions enable row level security;

-- Reference tables: authenticated users can read
drop policy if exists authenticated_read_units on public.business_units;
create policy authenticated_read_units
on public.business_units for select to authenticated
using (true);

drop policy if exists authenticated_read_categories on public.categories;
create policy authenticated_read_categories
on public.categories for select to authenticated
using (true);

-- Each user owns their accounts
drop policy if exists owner_manage_cash_accounts on public.cash_accounts;
create policy owner_manage_cash_accounts
on public.cash_accounts for all to authenticated
using (created_by = (select auth.uid()))
with check (created_by = (select auth.uid()));

-- Each user owns their transactions
drop policy if exists owner_manage_transactions on public.transactions;
create policy owner_manage_transactions
on public.transactions for all to authenticated
using (created_by = (select auth.uid()))
with check (created_by = (select auth.uid()));

-- Grants for API roles
grant select on public.business_units, public.categories to authenticated;
grant select, insert, update, delete
on public.cash_accounts, public.transactions to authenticated;

grant usage, select on sequence public.cash_accounts_id_seq to authenticated;
grant usage, select on sequence public.transactions_id_seq to authenticated;
```

## Bắt buộc rà soát sau khi chạy
1. Table Editor hiển thị đủ 4 bảng.
2. `business_units` có đúng 3 mảng.
3. RLS được bật trên cả 4 bảng.
4. Đăng nhập bằng user thử nghiệm rồi test truy cập.
5. Người chưa đăng nhập không được đọc/ghi bảng giao dịch qua API.
6. User A không được đọc/sửa/xóa giao dịch của User B.
7. Test insert giao dịch hợp lệ và không hợp lệ.

## Giới hạn và nâng cấp
- SQL trên không thiết kế chia sẻ giao dịch giữa nhiều user.
- Bảng `categories` hiện cho phép đọc bởi authenticated users; chỉ quản trị viên nên được thêm/sửa/xóa danh mục khi có mô hình role phù hợp.
- Cần kiểm tra tính tương thích giữa `category_id`, `transaction_type` và `business_unit_id` ở frontend; nên bổ sung constraint/trigger nếu cần bảo đảm tuyệt đối ở database.
- `updated_at` chưa tự cập nhật; nếu cần, tạo trigger riêng.
- Nếu muốn nhiều nhân viên cùng dùng chung một sổ thu chi, không chỉ nới RLS. Hãy chuyển sang mô hình tổ chức/thành viên và policy dựa trên membership.
